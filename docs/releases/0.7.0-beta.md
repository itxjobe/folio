# Folio 0.7.0-beta.1, for supporters

A build to hand to the people who paid for the Market before it existed. `versionName` is `0.7.0-beta.1` and
`versionCode` is `700`, the same code as the eventual `0.7.0`, so the real release installs straight over it and
nobody has to uninstall anything.

Everything in section 1 needs the release keystore, so only McCal can do it.

## 1. Build and sign it

One command. It reads the version out of `app/build.gradle.kts`, runs `:app:assembleRelease`, signs it, and writes
the APK, its checksum and the signing certificate into `dist/Folio-0.7.0-beta.1/`.

```bash
FOLIO_RELEASE_STORE_FILE=/path/outside/the/repo/folio-release.jks FOLIO_RELEASE_STORE_PASSWORD=… FOLIO_RELEASE_KEY_ALIAS=… FOLIO_RELEASE_KEY_PASSWORD=… ./scripts/release-signed.sh
```

It refuses to overwrite an existing `dist/Folio-0.7.0-beta.1/`, so delete that folder to build again.

What comes out:

| File | What it is |
|---|---|
| `Folio-0.7.0-beta.1.apk` | the build, signed with the release key |
| `SHA256SUMS.txt` | the checksum to publish beside it |
| `signing-certificate.txt` | the certificate digest, so anyone can check a later build came from the same key |

**The signature is the part that matters most here.** Folio only installs an update over itself when the new build
carries the same signature as the copy already on the phone. A beta signed with anything else does not install over
0.6.x, and Android's message for that says almost nothing useful.

The unsigned build has already been checked on the Fold8 (2026-09-20): R8 and resource shrinking are clean, the app
starts, runs its first-run setup, draws Home and opens the App Library with no crashes. What could not be checked
without a code is the Market itself, which is section 2.

## 2. Codes

A release build shows the Market only to a code. Mint them from the key that is already in `BetaKeys.SUPPORTER`:

```bash
./scripts/beta-code.py mint --scopes beta --count 10
```

`beta` is the scope that opens the Market. Add `keys` for Keyd and `look`/`power` for the other early features; a
code with no expiry never stops working, and `--expires YYYY-MM-DD` is there if a round of testing should end.

Redeeming one in Settings › Supporter opens the Market **and** turns on Beta Updates, so later betas arrive on their
own once `McCal-Codes/folio-beta` exists (see [0.7.0-github.md](0.7.0-github.md) section 1b). Until that repository
is there, beta.1 has to be sent as a file.

## 3. Before sending it

- Publish the SHA-256 next to the download, in whatever message carries the link.
- Run the APK through VirusTotal and link the report. A sideloaded launcher holding `REQUEST_INSTALL_PACKAGES`
  usually collects a heuristic flag or two from small engines; saying so up front reads better than letting someone
  find it.
- Point at [PERMISSIONS.md](../../PERMISSIONS.md). The plain list of what each permission is for is what actually
  settles people.

## 4. What is not in this build

Say these out loud rather than letting testers find them:

- **The supporter source is not added yet.** `SUPPORTER_SOURCE_KEY` is still empty, so redeeming a code opens the
  Market but adds no source with it. Adding a source by address works normally.
- **Keyd is not built.** Its listing is a design page, not something to install.
- **There is no community source to browse.** `folio-packages` publishes nothing until its key exists, so the
  Market has Folio's own nine packages and whatever address a tester adds.
- Settings schema pages and package scripts are 0.7.x, not this build.

## 5. What to ask them to try

1. **Open the Market from the Folio icon.** Featured, Sources, Packages, Installed, Settings. Does Settings still
   feel like Settings when it is a tab?
2. **Get a theme or a tweak, then Undo it.** The ring in the button, the message, the Undo beside it.
3. **Read a package page before getting it.** Does the privacy label say something they believe?
4. **Add a source by address** and open it. Its page should show the address it was added with, when it was signed,
   and everything it offers.
5. **Fold, unfold and rotate while the store is open.** The tab and the open package should survive all three.
6. **Turn on Settings › Market › Installing apps and read what it says.** Nobody has to install anything; the
   question is whether the setting explains itself.
7. **TalkBack and 200% text**, for anyone who uses either.

Ask for the device, the screen it happened on, and the Folio version from Settings › What's New. The "doesn't work
on my fold" report from the Z Fold 7 was worth more than any amount of guessing.
